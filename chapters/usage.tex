\chapter{このテキストの使い方}
\label{chap:usage}

\section{対象と到達目標}

本書は、Python を初めて学ぶ読者と、短い解析コードは書けるものの、実行環境の管理、結果の検証、再利用できる構成、高速化に不安がある読者を対象とする。読み終えた後には、次の作業を一つの解析手順として実行し、その選択理由を説明できることを目標とする。

\begin{itemize}
\item シェルでファイルとディレクトリを操作し、コマンドの標準出力と標準エラー出力を保存する。
\item Python のバージョンと仮想環境を管理し、解析に必要なライブラリとそのバージョンを記録する。
\item テキスト、表、バイナリデータを読み込み、型、欠損値、単位、時刻系を確認する。
\item 配列や表を整形・集計し、図、統計量、フィット結果を用いてデータの性質を調べる。
\item テストと測定に基づいて、解析結果を変えずにコードを整理し、高速化する。
\end{itemize}

すでに一部の内容を理解している場合は、必要な章から読み始めてもよい。ただし、後半の例では前の章で導入した用語とファイルを使用する。理解が曖昧な用語が現れた場合は、索引または本文中の参照先へ戻って確認する。

\section{章のつながり}

本書は、解析作業の順序に沿って四つの段階に分かれている。

\begin{enumerate}
\item シェルの章では、現在位置、パス、ファイル、実行ファイル、環境変数、入出力の流れを学ぶ。Python 環境の章では、その知識を用いて Python のバージョンとプロジェクトごとの環境を管理する。
\item Python の基本構文とデータ入出力の章では、短いスクリプトを読み書きし、ファイルから値を取り出して Python のオブジェクトへ変換する。
\item NumPy から Astropy までの章では、数値配列、表、図、統計処理、物理単位、時刻、天体データを扱う。各ライブラリの役割を比較し、同じデータを次の処理へ受け渡す。
\item 自作モジュールと性能改善の章では、解析処理をテスト可能な部品へ分け、実行時間とメモリ使用量を測定する。最後の総合課題では、ここまでの操作を一つの解析として組み合わせる。
\end{enumerate}

この順序は、特定のライブラリを使うこと自体ではなく、入力を確認してから計算し、結果を検証して保存する流れを身につけるためにある。例えば、pandas で表を読み込めても、ファイルの所在、区切り文字、文字コード、列型を確認できなければ、読込み結果の妥当性を判断できない。基礎的な操作は、後半の解析を検証するための手段でもある。

\section{コード例と実行結果の読み方}

コード例を読むときは、最初から各行の文法を完全に理解しようとせず、次の順序で処理の全体像を確認する。

\begin{enumerate}
\item 入力を確認する。変数、引数、ファイル名、配列の形状、単位が何かを調べる。
\item 処理を確認する。呼び出している関数と、関数へ渡している引数を追う。
\item 出力を確認する。返り値、表示内容、保存先のファイルを特定する。
\item 実行結果を本文の説明と照合する。数値、型、形状、行数、図の軸が想定どおりかを確認する。
\end{enumerate}

例えば、\code{values = np.loadtxt("data.txt")} という行では、\code{data.txt} が入力、\code{np.loadtxt()} が処理、\code{values} が返り値の保存先である。次に \code{values.shape} と \code{values.dtype} を表示すれば、行列の大きさと要素型を確認できる。関数名だけを覚えるのではなく、入力条件と返り値を実行結果に結び付けて読む。

コマンドやコードの実行例には、可能な範囲で代表的な出力を続けて示す。表示されるパス、バージョン番号、処理時間などは環境によって異なるため、文字列をそのまま一致させるのではなく、各行が何を表し、どの部分を確認すべきかを読む。図についても、コードだけでなく保存された出力例を示し、本文では軸、色、凡例、分布、残差のうち何を確認するかを説明する。

\section{章末問題の進め方}

各章の末尾には、その章だけを読み直して取り組める問題を置いている。問題文には、入力の作り方、使用する主な関数、保存するファイル名、確認すべき値をできる限り示した。最初に小さな検証用データで処理を確認し、その後に配布データまたは自分のデータへ適用する構成を基本とする。

数値の目安は、答えを書き写すためではなく、実装の誤りを検出するために使う。期待値と一致しない場合は、単位、境界条件、並べ替え、欠損値、データ型を順に確認する。図を提出する問題では、画像ファイルが作られたことだけでなく、軸ラベルと単位、凡例、対象範囲、データとモデルの対応を確認する。

第~\ref{chap:kadai}~章の総合課題では、複数の章で作った処理を連結する。課題用のスクリプトとデータの入手先は同章に記載している。まず配布コードをそのまま実行して入力と出力を把握し、小さなデータで正しさを確認した後に、大規模データの処理と性能改善へ進む。

\section{検証と記録}

データ解析では、コードが終了したことと、結果が正しいことを区別する。結果を確認するときは、次の観点を用いる。

\begin{itemize}
\item 件数、最小値、最大値、平均値などを、手計算できる小さな入力と比較する。
\item 配列の \code{shape} と \code{dtype}、表の列名と欠損値数を表示する。
\item 境界値を含む入力を作り、\code{<} と \code{<=} などの条件を検証する。
\item フィット値だけでなく、データ、モデル、残差を同じ図で確認する。
\item 高速化の前後で結果が一致することを確かめてから、同じ条件で処理時間を測る。
\end{itemize}

検証に使った入力、コマンド、ライブラリのバージョン、乱数シード、出力ファイルを記録しておけば、後から同じ結果を再現しやすい。解析コードを自作モジュールへ分け、テストを追加する作業も、この記録を実行可能な形にする方法の一つである。

\section{参考資料の使い分け}
\label{sec:reference-guide}

本文は単独で読み進められるように構成しているが、コマンドのオプションやライブラリの API は更新される。概念と代表例は本文で確認し、全引数、戻り値、バージョンごとの差異は公式資料で調べる。本文で引用した資料は巻末の参考文献にまとめている。

Python の言語仕様と標準ライブラリには、Python 公式チュートリアル~\cite{python_tutorial} と公式ライブラリリファレンス~\cite{python_library} を用いる。環境構築には JupyterLab、uv、pyenv の公式資料~\cite{jupyterlab_docs,uv_docs,pyenv_docs}、主要な解析ライブラリには各プロジェクトの公式資料~\cite{numpy_quickstart,pandas_tutorials,polars_concepts,matplotlib_quick_start,scipy_user_guide,astropy_user_guide} を参照する。

シェルコマンドは、OS や実装によってオプションが異なることがある。本文の例を実行する前後に、\code{command --help} または \code{man command} で手元の仕様を確認する。Git と GitHub の基本操作は付録~\ref{app:git}、SSH とファイル転送は付録~\ref{app:ssh} にまとめている。
